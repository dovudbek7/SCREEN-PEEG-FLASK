3. ① 配置するファイルと、必要な列

この章では、毎月 expenses/・attendance/ に配置する2つのファイルについて、 システムが何を読み取るかを説明します。まず、ファイルを配置するうえでのポイントは次の4点です。

  • ファイル名は問いません。システムがフォルダ内から自動でファイルを抽出するためです （出張精算CSVは最新1件、出勤簿はフォルダ内すべてを読み込みます）。
  • 列の並び順も問いません。システムは列見出しの名前で列を探すためです。
  • 列見出し（ヘッダ）の名前だけは、正確に一致している必要があります。 見出しが変わっていると、システムがその列を見つけられません。
  • 楽々精算・楽々勤怠からそのままエクスポートすれば、見出しは自動的に正しくなります。 問題が起きるのは、ファイルを手動で開いて列名を変更した場合のみです。
つまり、エクスポートしたファイルをそのまま置くだけで問題ありません。 以下の 3.1・3.2 の列一覧は、列名を変更してしまった場合や、エラーが出た場合にご確認ください。

4. ② 実行方法

  1. 1プロジェクトフォルダ直下の run.command（Windowsの場合は run.bat）をダブルクリックします。
  2. 2通常は何も聞かれません（既定パスワードが自動的に試されます）。社員・顧客リストのパスワードが変更されている場合のみ、ターミナルがパスワードを尋ねます — 入力してください（画面には表示されません）。
  3. 3自動で読込・突合・判定・出力が実行されます（数秒〜数十秒）。
  4. 4「✅ 完了しました」と表示されたら終了です。Enterキーでウィンドウを閉じてください。
初回実行時のみ実行環境の準備が入るため、数分かかることがあります（2回目以降は数秒〜数十秒）。 また実行前に expenses/・attendance/ が空でないか自動チェックされ、 空の場合はその場でメッセージを表示して停止します。
必要なファイルがフォルダに無い場合、列名が誤っている場合、またはパスワードを3回間違えた場合は、 エラーメッセージが表示され処理は中止されます。メッセージの指示に従ってファイルを配置し直すか、 パスワードを確認のうえ再度実行してください。

5. 運用の手順（ファイルの入れ替え方）

アップロードしたデータ単位でチェックシートを作成します。 expenses/・attendance/ とも、システムはフォルダ内の最新1ファイルのみを 読み込みます（入れ替え式）。週次で楽々精算・楽々勤怠を出力される運用のため、 ファイルを積み上げるとチェック対象が毎回増え続けてしまうことから、 最新に格納されたデータのみを抽出・突合する方式としております（2026-08-04 変更）。

フォルダシステムの読み込み方毎回の操作過去分の扱い
expenses/最新1ファイルのみ新しいCSVを配置（入れ替え）削除推奨（残っていても読み込まれません）
attendance/最新1ファイルのみ新しい出勤簿を配置（入れ替え）削除推奨（残っていても読み込まれません）
out/—（出力先）操作不要実行のたびに新フォルダが作られる。そのまま履歴として残せます
【重要】2つのファイルは必ず同じ期間のものを組み合わせてください。
システムは expenses/ の最新CSVと attendance/ の最新出勤簿を突合します。 出張精算CSVに含まれる出張日の勤怠が、出勤簿側に無い場合、その申請は 未確認（勤怠データ欠落） となり、出張実態・労務の判定ができません。
たとえば出張精算CSVが4か月分、出勤簿が1か月分だと、残り3か月分の申請はすべて 未確認 になります。 同じ週（同じ期間）にエクスポートした2ファイルをセットで配置してください。

5.1. 最新1ファイルの判定方法

システムはファイル名に含まれる数字（タイムスタンプ）で新旧を判断します。 楽々精算・楽々勤怠からエクスポートしたファイル名（例：出勤簿_日別詳細_20260630085826.xlsx）を そのままご利用いただければ問題ありません。

ファイル名を手動で変更しないでください。ファイル名の数字と中身の対象期間が食い違うと、 意図しないファイルが「最新」と判定されることがあります。

5.2. out/ — 操作不要

実行のたびに out/YYYYMMDD_HHMMSS/ という新しいフォルダが自動作成されます。 既存のフォルダが上書きされることはないため、削除は不要です。過去の実行結果をそのまま履歴として保管できます。

5.3. 毎回の作業手順（まとめ）

  1. 1expenses/ 内の古いCSVを削除し、新しくエクスポートした出張精算CSVを配置
  2. 2attendance/ 内の古い出勤簿を削除し、同じ期間の出勤簿を配置
  3. 3run.command / run.bat を実行
  4. 4out/ の最新フォルダを開き、結果を確認
古いファイルを残しても読み込まれないため動作上の問題はありませんが、 どのファイルが使われたか分かりにくくなるため、削除を推奨します。 実際に読み込まれたファイル名は 05_取込ログ シートでご確認いただけます。

8. 定時外の移動時間（勤務実態）の見方

01_一次承認チェック の「2. 労務・健康管理の確認」グループは18列で構成され、 1日を3つの時間帯に分けて、楽々精算（申請された移動時刻）と 楽々勤怠（実際の勤怠記録）を左右に並べて比較します。

時間帯範囲列
定時前〜 9:00精算 開始／終了、勤怠 開始／終了、定時前差分、定時前チェック
勤務時間9:00 〜 17:30精算 開始／終了、勤怠 開始／終了、勤務差分、勤務チェック
定時後17:30 〜精算 開始／終了、勤怠 開始／終了、定時後差分、定時後チェック

8.1. 判定ルール

  • 各時間帯で開始・終了の両方を比較し、差が大きいほう（悪いほう）を採用します。
  • 10分以内 → OK／11分以上 → 要確認。この項目に NG はありません。
  • 精算・勤怠のいずれかで開始または終了のデータが欠けている場合は、差分欄に「データなし」と表示し、 チェックは 要確認 になります。
2026-07-27 のご依頼により、平日・休日を問わず 9:00／17:30 の定時境界で判定します （それ以前は休日を別扱いにしていました）。

8.2. 複数日の出張の表示（2026-07-31 変更：日単位表示）

従来は申請（伝票）1件＝1行だったため、2泊3日の出張では 「1日目の定時前」と「3日目の定時後」しか表示されず、中日の移動が見えませんでした。 ご指摘を受け、1日＝1行で表示する方式に変更いたしました。 1件の申請は、明細日付の日数分の行に展開されます。

実例（4日間の出張、2026-04-01 〜 2026-04-04）：

日付定時前（精算）勤務時間（勤怠）定時後（精算）差分
04-01—09:00 〜 18:3018:30 〜 19:00勤務 一致
04-02—09:00 〜 17:3017:30 〜 23:15定時後 0:23差
04-0308:00 〜 09:0009:00 〜 21:0021:00 〜 21:30勤務 一致
04-0407:45 〜 09:00——定時前 0:33差

8.2.1. 行の展開ルール

  • 行は 明細日付 の昇順に並びます。新しく 日付 列を追加しました （出張実態 の右隣）。
  • その日の移動を 9:00／17:30 の境界で 定時前・勤務時間・定時後 に振り分けます。 1日に2回の移動（移動開始/終了 と 移動2開始/終了）がある場合も、 それぞれ該当の時間帯へ振り分けます。
  • 伝票単位の項目（合計金額・日当計・総合判定・取引先・二重申請確認など）は、 その伝票の先頭日の行にのみ表示されます。2日目以降は空欄です。 これは合計金額を集計した際に日数分だけ多重計上されるのを防ぐためです。
  • Excelでは伝票が切り替わるたびに背景色を交互に塗り分けており、 どこからどこまでが1件の申請かひと目で分かるようにしています。
HTMLレポートの検索・絞り込みについて：検索や絞り込みは伝票単位で動作します。 たとえば「要確認」で絞り込むと、該当する伝票の全日分の行がまとめて表示されます。 日付で検索した場合も、その日を含む伝票の全日分が表示されます。 件数表示（◯◯件）も行数ではなく伝票件数です。

8.3. 総合判定への反映（2026-07-30 変更）

従来この3つのチェックは表示専用で、総合判定には反映していませんでした （勤務チェックが 要確認 でも総合判定が OK となる状態）。 ご指摘を受け、次のとおり総合判定に反映するよう変更しました。

差分の状態チェック欄の表示総合判定への反映
時刻差が11分以上要確認反映する → 総合判定も要確認
時刻差が10分以内／一致OK影響なし
「データなし」要確認反映しない
「データなし」を総合判定に反映しない理由：「データなし」は比較する材料が無い状態であり、 実際に時刻がずれている証拠ではないためです（多くは楽々勤怠側に移動時刻の打刻が無いケース）。 これを反映すると、ほぼ全件が要確認となり判定の意味が薄れてしまいます。 なお、チェック欄の表示は 2026-07-17 にご確認いただいた仕様どおり 要確認（黄色）のまま変更しておりません。
総合判定に反映された場合は、要確認項目 列に「定時外移動時間」と表示され、 03_差異一覧 にも該当の時間帯と差分が出力されます。
